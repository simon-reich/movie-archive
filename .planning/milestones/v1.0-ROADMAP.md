## Overview

Personal web app to build a searchable film archive. Movies are fetched via TMDB, optionally enriched with OMDB and Wikipedia data, then indexed in OpenSearch for full-text and faceted search. Designed for personal use today, architected to support multiple users later.

## Milestone Summary

### Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| JwtAuthFilter without @Component | Prevents double-registration in SecurityFilterChain | ✓ Good |
| grace_until 5s on refresh token | Handles concurrent tab race condition | ✓ Good |
| forgotPassword always 200 OK | Enumeration protection | ✓ Good |
| AES-256-GCM for API keys | API keys at rest encrypted, master key from ENV | ✓ Good |
| Save-flow async (202 Accepted) | External API calls don't block UX | ✓ Good |
| Snapshot strategy for film data | No runtime dependency on TMDB after save | ✓ Good |
| movies-{userId} index per user | Data isolation at infra level, easy multi-user extension | ✓ Good |
| GenericContainer for OS Testcontainers | opensearch-testcontainers 4.x incompatible with OS 2.x | ✓ Good |
| withJson() pattern for index creation | opensearch-java typed builder bug #1510 | ✓ Good |
| auth.getName() returns email | UserDetailsServiceImpl uses email as username — ownership checks use findByEmail | ✓ Good |
| Refresh.WaitFor on index() | Document immediately searchable — fixes E2E Mobile Chrome race condition | ✓ Good |
| Tailwind viewport breakpoints for star rating | Container queries failed due to flex shrink-to-fit sizing | ✓ Good |
