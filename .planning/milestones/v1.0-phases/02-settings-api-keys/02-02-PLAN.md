**EncryptionService.java:** Exact implementation from RESEARCH.md Pattern 1. Class annotated `@Service`. Constructor injects `@Value("${encryption.master-key}") String masterKeyStr`. Uses `Arrays.copyOf(keyBytes, 32)` to ensure exactly 32 bytes. `encrypt()` generates `new byte[12]` IV via `new SecureRandom().nextBytes(iv)`, encrypts with `Cipher.getInstance("AES/GCM/NoPadding")` and `GCMParameterSpec(128, iv)`, returns `Base64.getEncoder().encodeToString(combined)` where combined = IV + ciphertext. `decrypt()` splits: `iv = Arrays.copyOfRange(combined, 0, 12)`, `ciphertext = Arrays.copyOfRange(combined, 12, combined.length)`. Use `java.util.Base64` (not `javax.xml.bind`). Catch `Exception` and throw `IllegalStateException("Encryption failed", e)`.

**SettingsService.java:** `@Service @Transactional @Slf4j`. Constructor injects: `UserRepository`, `UserApiKeyRepository`, `RefreshTokenRepository`, `BCryptPasswordEncoder`, `EncryptionService`, `TmdbKeyValidator`, `OmdbKeyValidator`, `EmailChangeTokenRepository` (from `de.moviearchive.token`), `MailService`, `@Value("${app.base-url}") String appBaseUrl`.

Methods:

`saveApiKey(String email, String providerStr, String rawKey)`:
1. Parse provider: `ApiKeyProvider provider = ApiKeyProvider.valueOf(providerStr.toUpperCase())` — throws `IllegalArgumentException` if invalid (controller catches as 400).
2. Validate key: call `tmdbKeyValidator.validate(rawKey)` or `omdbKeyValidator.validate(rawKey)` based on provider. If returns false → throw `InvalidApiKeyException("Invalid " + providerStr + " API key — check your key and try again.")`.
3. Load user by email (throw `UsernameNotFoundException` if not found).
4. Upsert: `userApiKeyRepository.findByUserIdAndProvider(user.getId(), provider)` — if present, update `existing.setEncryptedKey(encryptionService.encrypt(rawKey))` and save; if absent, save new `UserApiKey(user, provider, encryptionService.encrypt(rawKey))`.
5. Log INFO: `"API key saved for provider={} userId={}"` — NEVER log the key or encrypted blob.

`getApiKeys(String email)`: Load user. For each provider (TMDB, OMDB), call `findByUserIdAndProvider` and decrypt if present, else null. Return `Map.of("tmdb", tmdbPlaintext, "omdb", omdbPlaintext)` — null values included.

`changePassword(String email, String currentPassword, String newPassword)`:
1. Load user by email.
2. `if (!passwordEncoder.matches(currentPassword, user.getPasswordHash()))` → throw `BadCredentialsException("Current password is incorrect.")`.
3. `user.setPasswordHash(passwordEncoder.encode(newPassword))`.
4. `userRepository.save(user)`.
5. `refreshTokenRepository.revokeAllByUserId(user.getId())` — identical to `AuthService.resetPassword()` pattern.

`requestEmailChange(String email, String newEmail)`:
1. Load user by email (current user).
2. Create raw token: `UUID.randomUUID().toString()`. Hash: `TokenUtils.hashToken(rawToken)`.
3. Save `new EmailChangeToken(user, newEmail, hash, Instant.now().plus(24, ChronoUnit.HOURS))`.
4. Call `mailService.sendEmailChangeConfirmation(newEmail, rawToken)` — sends confirm link to new address.
5. Return silently (200). Do NOT check if `newEmail` is already taken at this point (enumeration protection, D-07/RESEARCH pitfall 4).

`confirmEmailChange(String rawToken)`:
1. Hash token and look up in `emailChangeTokenRepository.findByTokenHash(hash)` — throw `TokenNotFoundException` if absent.
2. Check `isExpired()` → throw `TokenExpiredException`. Check `isConsumed()` → throw `TokenAlreadyConsumedException`.
3. Re-check email uniqueness: `if (userRepository.existsByEmail(token.getNewEmail()))` → throw `EmailAlreadyExistsException` (controller returns 409 with `{"message": "This email address is no longer available."}`).
4. Consume: `token.setConsumedAt(Instant.now())`. Save.
5. Update user: `user.setEmail(token.getNewEmail())`. Save.
6. Send notification to old email: `mailService.sendEmailChangeNotification(oldEmail)` where `oldEmail` is the user's email BEFORE the update. Capture it before step 5.

    Context ctx = new Context();
    // Link must go through /api/settings/confirm-email so Caddy routes to Spring (Pitfall 7)
    ctx.setVariable("confirmUrl", baseUrl + "/api/settings/confirm-email?token=" + rawToken);

        helper.setFrom(fromAddress);
        helper.setTo(toNewEmail);

        helper.setText(htmlContent, true);

        log.info("Email change confirmation sent to new address");
    } catch (Exception e) {
        log.error("Failed to send email change confirmation: {}", e.getMessage());

| Boundary | Description |
|----------|-------------|
| client→PUT /settings/api-keys/{provider} | User-supplied API key string; validated against external API before storage |
| Spring→TMDB API / OMDB API | WebClient outbound call; external service returns 200 or 401 |

| client→GET /settings/confirm-email?token=... | Token in URL query string; must be SHA-256 hashed and single-use |
