<objective>
Build the Bulk Import Engine: a multipart upload endpoint that parses a semicolon-delimited
Title;OriginalTitle;Year film list, matches each line against TMDB filtered by exact release
year, auto-saves unique matches through the existing idempotent save+enrich pipeline, flags
ambiguous matches for later manual review, and skips lines already saved on re-upload without
re-hitting TMDB.

Purpose: This is the backend engine Phase 11's live-progress/results UI will read from —
Phase 10 owns parsing, matching, saving, and the per-line bulk_import_line persistence that
makes every outcome (saved/ambiguous/not_found/parse_error) durable and re-upload-safe.
Output: New `bulkimport` package (controller, async service, entity, repository, parser),
a new `bulk_import_line` table, and extensions to TmdbClient/TmdbSearchResultItem/MovieService/
AsyncConfig needed to support it.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser -> BulkImportController | Untrusted multipart file content and per-line free text crosses here |
| BulkImportController -> BulkImportService (async handoff) | Extracted raw line list crosses a thread boundary (request thread -> bulkImportExecutor thread) |
| BulkImportService -> TMDB API | Line title/originalTitle text is sent to TMDB as a search query |
| BulkImportService -> bulk_import_line / movies tables | User-supplied free text (title, original_title, raw_line) is persisted |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-01 | Denial of Service | BulkImportController.uploadBulkImport (file upload) | medium | mitigate | Rely on Spring Boot's default multipart limits (max-file-size=1MB, max-request-size=10MB) — no override added in application.properties — the multipart resolver returns 413 automatically before the controller method runs; no custom code needed. |
| T-10-02 | Tampering / Elevation of Privilege | BulkImportController user resolution | high | mitigate | userId is resolved exclusively from `Authentication.getName()` (JWT subject email) -> `UserRepository.findByEmail()`; there is no path-variable or request-body user identifier on this endpoint at all, so there is no IDOR surface to guard — every `bulk_import_line`/`Movie` read/write is scoped to this server-resolved user. |
| T-10-03 | Tampering (log forging) | BulkImportService logging of user-supplied titles | low | mitigate | All log statements use SLF4J parameterized placeholders (`log.info("...title={}...", title)`), never `String.format`/concatenation with raw uploaded line content — consistent with the codebase's `@Slf4j` convention. |
| T-10-04 | Tampering (data integrity) | BulkImportLine.title/originalTitle persistence | medium | mitigate | User-supplied title/originalTitle text is capped to 500 characters before persisting (matches the `VARCHAR(500)` column width, identical to `movies.title`/`movies.original_title`), preventing a persistence-layer exception from an oversized malformed line from aborting the batch job. |
| T-10-05 | Information Disclosure | POST /movies/bulk-import authentication | high | mitigate | No new SecurityConfig matcher is added — `/movies/bulk-import` falls under the existing `.anyRequest().authenticated()` rule (it is not in the `permitAll()` list), identical to every other `/movies/**` endpoint. |
| T-10-06 | Denial of Service | bulkImportExecutor unbounded overlap | medium | mitigate | `bulkImportExecutor` is a bounded `core=1/max=1/queue=1` executor, mirroring `wikiReloadExecutor` — a third overlapping trigger is rejected with 503 before it ever reaches business logic (T-10-SC not applicable — no package installs in this phase). |
</threat_model>
