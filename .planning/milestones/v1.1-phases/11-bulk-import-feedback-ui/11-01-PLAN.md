Give every bulk-import upload a durable batch identity (D-02) and capture each SAVED line's
poster path at save time (D-04), so Phase 11's later plans (SSE progress, batch list/detail
endpoints, frontend results UI) have real persisted data to read instead of ephemeral state.

Purpose: D-02 is the foundation the rest of this phase depends on — CONTEXT.md calls it a
one-way door (requires a schema migration; reversing it later means migrating data again).
Getting the batch/line relationship and poster capture right here means every later plan in
this phase reads correct data, with zero backfill needed.
Output: `bulk_import_batch` table, `BulkImportBatch` entity/repository, `BulkImportLine`
gains `batch`/`posterPath` fields, `BulkImportService` threads a real `batchId` through the
whole async pipeline and captures `posterPath` on every SAVED line, `POST /movies/bulk-import`
returns the new `batchId` in its response body.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Client -> POST /movies/bulk-import | Untrusted multipart upload; response now echoes back a server-generated `batchId` |
| BulkImportService (async) -> Postgres | `batchId` used to attach lines to a batch — must always originate server-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-01 | Tampering | BulkImportService.processLine/upsertLine | low | mitigate | `batchId` is only ever obtained from `bulkImportService.createBatch()`'s return value inside the same request/async chain — never accepted from client-supplied path/body params in this plan, so a line can never be attached to a batch the client chose. The client-visible `batchId` returned in the POST response only becomes a lookup key once Plan 11-03's ownership-checked GET endpoints exist. |
| T-11-02 | Information Disclosure | bulk_import_batch.total_lines | low | accept | `total_lines` reflects the raw uploaded line count (including blank lines, per Pitfall 4) — not a security-sensitive value, and only readable by the batch's owner once Plan 11-03 adds the read endpoints (no read endpoint exists yet in this plan). |
</threat_model>
