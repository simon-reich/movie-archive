## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser -> GET /movies/bulk-import/{batchId}/progress (SSE) | Frontend must send the same `Authorization: Bearer` header as every other authenticated call in this app — never a query-param token |
| npm registry -> frontend/package.json | New third-party dependency install |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-SC | Tampering | `pnpm add @microsoft/fetch-event-source` | high | mitigate | Package Legitimacy Audit already completed in 11-RESEARCH.md: verdict OK, ~3.2M weekly downloads, maintained by Microsoft, no `postinstall` script — disposition Approved, no blocking-human checkpoint required per the audit's own verdict (not `[ASSUMED]`/`[SUS]`). |
| T-11-08 | Information Disclosure | subscribeToProgress() onerror handling | low | mitigate | `onerror` re-throws on any non-retriable status (Pitfall 3) instead of letting the library retry indefinitely against a 403/404 — prevents request spam that could otherwise be used to probe for the existence of other users' batchIds via timing/response patterns. |
| T-11-09 | Spoofing | GET .../progress auth | medium | mitigate | Uses `@microsoft/fetch-event-source` with the existing `authHeaders()` Bearer-token helper, never native `EventSource` (which cannot attach the header at all and would silently 401) — see 11-RESEARCH.md Pitfall 1. |
</threat_model>
