<objective>
Make `WikipediaClient.fetch()` resolve Wikipedia articles via a direct Wikidata IMDb-ID (P345) cross-reference first, before falling back to the existing 6/10-step candidate-URL guessing cascade — applied automatically to every caller (save flow, manual retry, batch-reload) with zero caller-side special-casing. Add a temporary, human-readable per-attempt resolution log so the user can see whether each lookup resolved via Wikidata or the fallback cascade.

Purpose: Replace unreliable URL-guessing with Wikidata's purpose-built external-ID cross-reference for an unambiguous, single-request-chain resolution, while giving the user visibility into which path each Wikipedia enrichment attempt took (previously invisible).
Output: `WikipediaClient.tryFetchViaWikidata()` wired into `fetch()`, a second `WebClient` bound to `wikidata.base-url`, WireMock test coverage of the happy path and all documented fall-through cases, and a plain-text `wiki-resolution.log`.
</objective>
