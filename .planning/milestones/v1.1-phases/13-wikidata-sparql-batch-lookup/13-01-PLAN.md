<objective>
Replace WikipediaClient's per-movie, two-REST-call Wikidata lookup with a single batched SPARQL
query against query.wikidata.org that resolves many IMDb IDs to enwiki article titles in one
request (D-01), and remove the temporary Phase-12 dev-visibility resolution log entirely (D-04).

Purpose: this is the phase's foundation — Plan 2 (WikiReloadService.batchReload) and Plan 3
(BulkImportService/EnrichmentService) both depend on the public API this plan creates
(resolveViaWikidataSparql() and the Map-aware fetch() overload) to actually exploit batching,
rather than swapping the REST endpoint for a SPARQL endpoint while still calling it once per movie.
Output: WikipediaClient exposes one Wikidata resolution method used by every caller shape (a
single IMDb ID, or a pre-resolved batch map), fully tested against WireMock, with the old
two-call REST flow and the dev-visibility log deleted.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-01 | Tampering | WikipediaClient.resolveChunkViaWikidataSparql (SPARQL query construction) | low | mitigate | IMDb ID values originate exclusively from TMDB's `external_ids.imdb_id` field (never user-typed free text) and are shape-validated as `tt\d+` by TMDB itself before ever reaching this method (V5 Input Validation, per RESEARCH.md Security Domain). Each ID is still wrapped in double quotes as a SPARQL string literal inside the VALUES clause, as defense-in-depth against the (currently unreachable) case of a malformed id reaching this code path. |
| T-13-02 | Denial of Service (self-inflicted against Wikidata) | WikipediaClient.resolveViaWikidataSparql | high | mitigate | Unbounded batch size or unpaced requests against the Query Service can escalate to a 24-hour IP ban (RESEARCH.md Pitfall 5) — materially worse than a single 429. Mitigated by the SPARQL_CHUNK_SIZE=50 cap and reuse of the existing shared `paceRequest`/`recordRateLimited`/`backoffUntil` mechanism unchanged, exactly as this project's two prior live rate-limit incidents (Wikipedia REST, Wikidata REST) drove the same pattern for the methods this task removes. |
| T-13-SC | Tampering | package installs | n/a | accept | No new npm/pip/cargo/Gradle dependency is introduced by this plan (RESEARCH.md Package Legitimacy Audit: "Not applicable") — the package-legitimacy gate does not apply. |
