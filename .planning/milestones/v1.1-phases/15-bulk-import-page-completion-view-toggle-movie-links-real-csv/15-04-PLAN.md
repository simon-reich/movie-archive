<objective>
Close two UAT gaps found in Phase 15's bulk-import batch-detail page (`frontend/pages/imports/[batchId].vue`),
both fully diagnosed with root cause and fix direction in `.planning/debug/`:

G-15-2: SAVED cards silently fail to navigate (a documented Nuxt 3 limitation — `:is` bound to the bare string
`'NuxtLink'` inside a ternary is invisible to Nuxt's build-time component-registration scan, so it renders an
inert unresolved custom element instead of a link); PARSE_ERROR lines still render inside a poster-shaped card
that truncates the raw string that is the entire point of a PARSE_ERROR display; and results are not grouped by
status into the four sections the user explicitly asked for (Saved -> Ambiguous -> Not found -> Parse error).

G-15-3: the inline resolve widget's candidate picker is nested inside the single grid-cell/row-column of the line
it belongs to, so candidate posters are squeezed too small to recognize.

Purpose: make the SAVED-line link actually work in the real (un-stubbed) Nuxt runtime, make PARSE_ERROR lines
genuinely diagnosable (full raw string, never truncated by a poster shape), give the user the outcome-grouped
layout they asked for, and make the resolve widget's candidate picker actually usable at real poster size.

Output: `[batchId].vue` rewritten with a working NuxtLink resolution, four ordered status sections, an
always-row PARSE_ERROR treatment, and a full-width resolve-candidate panel; `imports-batchId.spec.ts` extended
with a source-level NuxtLink regression guard plus new tests proving PARSE_ERROR's always-row behavior, the
four-section grouping/ordering, and the resolve panel's full-width DOM placement.
</objective>
