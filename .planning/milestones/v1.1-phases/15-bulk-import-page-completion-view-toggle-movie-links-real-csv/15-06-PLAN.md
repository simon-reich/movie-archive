<objective>
Close UAT gap G-15-5: the title+year candidate label added by 15-05 (for G-15-4) works correctly for short
titles, but for longer movie titles the label's `truncate` Tailwind utility (overflow-hidden + ellipsis +
whitespace-nowrap) forces the whole "Title (Year)" string onto one line and clips it once it overflows the
narrow candidate-cell width — since the year is appended at the end of the same string, it gets cut off entirely
along with the tail of the title. User verbatim (re-test after 15-05): "Ja, schon besser. Problem ist, dass
längere Titel nicht ganz dargestellt werden und damit auch die Jahreszahl verloren geht. Also, da muss es
irgendwie einen Zeilenumbruch geben, sodass der Titel komplett dargestellt wird, nicht mit Punkt abgekürzt wird.
So dass der komplette titel und dann auch noch die Jahreszahlen zu sehen ist." (need line-wrap instead of
ellipsis-truncation so the full title AND year are always visible).

Root cause is already confirmed (no debugging needed): both `resolve-candidate-label` elements
(`frontend/pages/imports/[batchId].vue`, grid view ~line 321 and list view ~line 423) carry class
`"text-[10px] text-muted-foreground text-center leading-tight truncate mt-1"`. This is exactly the `truncate`
utility 15-01/15-05 already use elsewhere for genuinely single-line contexts (line title, status label) — it is
simply not appropriate here, where the year at the end of the string must stay visible.

Purpose: make every candidate's full title and year always visible, so a long title never hides the very
information (the year) the label exists to disambiguate.

Output: both `resolve-candidate-label` elements in `[batchId].vue` drop `truncate` from their class list so
`candidateLabel()`'s text wraps onto multiple lines instead of being clipped; `imports-batchId.spec.ts` extended
to assert the class no longer includes `truncate` and that a long-title candidate's full label text (title +
year, un-clipped) is present in the rendered DOM.
</objective>
