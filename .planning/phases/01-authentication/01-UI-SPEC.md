| Property | Value |

## Scope: Pages in This Phase

| Route | Purpose |
|-------|---------|
| `/login` | Email + password login |
| `/signup` | New account registration |
| `/verify-email-sent` | Post-signup confirmation screen |
| `/verify-email` | Email verification link landing page |
| `/forgot-password` | Request password reset email |
| `/reset-password` | Set new password via reset token |

All six routes are public (unauthenticated). Every other route redirects to `/login` via server-side middleware.

## Page Layout

All auth pages share a single centered-card layout:

- Full-viewport height: `min-h-screen`
- Background: `bg-background` (dominant surface)
- Content: single card centered horizontally and vertically (`flex items-center justify-center`)
- Card: `bg-card` surface, `border border-border`, `rounded-lg`, shadow `shadow-sm`
- Card width: `w-full max-w-sm` (384px) with `p-6` inner padding
- No navigation bar, no sidebar on auth pages
- App name "MovieArchive" as a text heading above the card (not a logo image)

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, helper text offset |
| sm | 8px | Input-to-error-message gap, label-to-input gap |
| md | 16px | Between form fields, card inner padding sections |
| lg | 24px | Card padding (`p-6`), between form and card heading |
| xl | 32px | Vertical centering buffer above the card on tall viewports |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Touch targets for submit buttons: minimum 44px height (Tailwind: `h-11`)
- Form submit button: full card width (`w-full`)

## Color

| Role | CSS Token | Light Value | Usage |
|------|-----------|-------------|-------|
| Dominant (60%) | `bg-background` | `hsl(0 0% 100%)` — white | Page background |
| Secondary (30%) | `bg-card` | `hsl(0 0% 100%)` | Auth card surface (same as bg in light; differentiated in dark) |
| Border/Input | `border-border`, `border-input` | `hsl(214.3 31.8% 91.4%)` | Input borders, card border |
| Accent (10%) | `bg-primary` | `hsl(222.2 47.4% 11.2%)` — near-black navy | Submit button background |
| Destructive | `text-destructive` / `bg-destructive` | `hsl(0 84.2% 60.2%)` — red | Inline form error text only |
| Muted text | `text-muted-foreground` | `hsl(215.4 16.3% 46.9%)` | Helper text, placeholder, link subtitles |

**Accent reserved for:**
- Submit / primary CTA button background (`bg-primary text-primary-foreground`)
- Focus ring on interactive elements (`ring-ring`)

**Destructive reserved for:**
- Inline form error messages (`text-destructive`)
- No destructive actions exist in Phase 1 (no delete, no account removal)

Dark mode tokens are declared in `main.css` `.dark {}` block — do not override them.

## Form Anatomy Contract

Every form on an auth page follows this exact structure:

```
Card
  Card header
    App name (Display)              ← "MovieArchive" — text only, above card
    Page heading (Heading)          ← e.g. "Sign in to your account"
    Subtext (Body/muted)            ← optional secondary line
  Card body
    [Form fields — see below]
    Form-level error banner         ← only when API returns an error
    Submit button (full width)
  Card footer
    Navigation link                 ← e.g. "Don't have an account? Sign up"
```

### Field Anatomy

```
<label>  ← text-sm font-semibold text-foreground
<input>  ← border border-input bg-background text-sm rounded-md h-10 px-3
           focus-visible:ring-2 ring-ring ring-offset-2 outline-none
<p>      ← text-sm text-destructive mt-1  (only rendered when field has error)
```

### Form-level error banner (D-08)

Appears directly below the last field, above the submit button. Never a toast.

```
<div class="rounded-md bg-destructive/10 border border-destructive/30 px-3 py-2 text-sm text-destructive">
  {error message from API .message field}
</div>
```

Hidden by default. Rendered only when the API responds with an error. Persists until the user modifies any field or resubmits.

## Interaction States

### Inputs

| State | Visual |
|-------|--------|
| Default | `border-input` |
| Focused | `ring-2 ring-ring ring-offset-2 border-input` |
| Error | `border-destructive` + error `<p>` below |
| Disabled | `opacity-50 cursor-not-allowed` |

### Submit Button

| State | Visual |
|-------|--------|
| Default | `bg-primary text-primary-foreground hover:bg-primary/90` |
| Loading | Disabled + spinner icon (lucide `Loader2` with `animate-spin`) + label changes to "..." |
| Disabled | `opacity-50 cursor-not-allowed` |

Button is disabled and shows spinner while the API request is in-flight. Re-enabled after response (success or error).

### Rate Limit (D-07)

When API returns HTTP 429:
- Form-level error banner shows: `"Too many attempts. Try again in {X} seconds."` where X is parsed from the `Retry-After` response header.
- Submit button remains disabled for the duration (countdown via `setInterval`; button label shows `"Try again in {X}s"`).

## Client-Side Validation Rules

Validation runs on submit (not on each keystroke). Errors clear when the user modifies the relevant field.

| Field | Rule | Error Message |
|-------|------|---------------|
| Email | Non-empty + basic regex (`/.+@.+\..+/`) | `Enter a valid email address.` |
| Password (signup) | Minimum 8 characters | `Password must be at least 8 characters.` |
| Password (reset — new) | Minimum 8 characters | `Password must be at least 8 characters.` |
| Confirm password | Must match new password field | `Passwords do not match.` |
| All required fields | Non-empty | `This field is required.` |

Login password field: no client-side length validation (avoids leaking policy info; let backend reject).

## Accessibility

- All inputs have an associated `<label>` with matching `for`/`id`.
- Error messages are associated via `aria-describedby` pointing to the error `<p>` element.
- Form-level error banner has `role="alert"` so screen readers announce it immediately.
- Submit button disabled state uses `disabled` attribute (not just visual opacity).
- Focus order follows DOM order (top to bottom through fields, then button, then footer link).
- Minimum contrast ratio 4.5:1 for all text (satisfied by shadcn default token values).
