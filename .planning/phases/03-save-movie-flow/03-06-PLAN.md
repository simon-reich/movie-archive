<objective>
Close UAT gap from test 7: duplicate save triggered enrichment again, showed identical
spinner → success UX, and wasted a full async enrichment cycle for a film already in Postgres.

Root causes (diagnosed — do not re-investigate):
1. Backend: `MovieService.initiate()` returns only a UUID. The controller calls
   `enrichmentService.enrich(movieId)` unconditionally, even for existing movies.
2. Frontend: on page load and every new search, all results start with `state: 'idle'`,
   so the in-session duplicate guard `if (item.state !== 'idle') return` is bypassed.

Fix:
- Introduce `MovieInitiateResult` record (UUID id, boolean isNew).
- `MovieService.initiate()` returns this record.
- `MovieController.saveMovie()` only calls `enrichmentService.enrich()` when `isNew == true`.
- Add `GET /movies/saved-ids` returning `{ tmdbIds: [12345, ...] }`.
- `useMovies` composable exposes `getSavedTmdbIds()`.
- `add.vue` calls `getSavedTmdbIds()` on `onMounted` and after each search result is
  rendered; items whose tmdbId is already in the saved set start with `state: 'success'`
  so they are visually distinct and unclickable.

Purpose: SAVE-01 idempotency — a film saved by the user must never trigger duplicate enrichment.
Output: Backend guard + frontend pre-marking. All existing tests continue to pass.
</objective>
