<objective>
Add a Settings-page button that triggers Phase 8's batch Wikipedia reload for the current user, backed by a new lightweight `GET /users/me` identity endpoint (the first controller in the empty `de.moviearchive.user` package, since the frontend has no other way to learn its own user id).

Purpose: Implements the folded todo "Add batch wiki-reload trigger button to UI" per CONTEXT.md D-06/D-07 — Phase 8 shipped `POST /admin/wiki-reload/{userId}` as an endpoint with no UI trigger. This plan adds only the trigger; the batch-reload logic itself (cooldown filtering, pacing, 503-on-conflict) is unchanged from Phase 8.
Output: `GET /users/me` backend endpoint, `getCurrentUserId()`/`triggerWikiReload()` frontend composable functions, and a new "Wikipedia Data" section on `/settings`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser → `GET /users/me` | Authenticated request; the response body crosses back to the browser and must never include sensitive `User` fields |
| Browser → `POST /admin/wiki-reload/{userId}` (existing, Phase 8, unchanged) | `userId` supplied by the frontend, sourced only from `GET /users/me`, which is always the caller's own id |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-04 | Information Disclosure | `UserController.me` | high | mitigate | Returns `Map.of("id", id)` — never the raw `User` JPA entity, which has no `@JsonIgnore` guard on its password-hash column; Task 2 adds an explicit test asserting that field is absent from the response body |
| T-09-05 | Spoofing / Broken Authentication | `GET /users/me` | low | mitigate | No new `permitAll()` entry added to `SecurityConfig` — `/users/me` falls under the existing `anyRequest().authenticated()` catch-all guarded by `JwtAuthFilter`; Task 1 adds a test confirming an unauthenticated request is rejected |
| T-09-06 | Elevation of Privilege (IDOR on downstream trigger) | Settings-page call to `POST /admin/wiki-reload/{userId}` | low | accept | `GET /users/me` is self-scoped by construction (returns only the caller's own id, derived from their own JWT) — the frontend can never obtain another user's id through this endpoint, and the downstream POST already enforces `assertOwnership` (Phase 8, unchanged, out of this phase's scope) |
</threat_model>
