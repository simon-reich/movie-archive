<objective>
Restructure WikiReloadService.batchReload() to prefetch Wikidata data for every cooldown-eligible
movie in one (or a few chunked) SPARQL call(s) before its per-movie loop starts, instead of
resolving Wikidata per movie inside the loop (D-02).

Purpose: Plan 1 built the batching primitive (WikipediaClient.resolveViaWikidataSparql() and the
Map-aware fetch() overload); calling that primitive once per movie from inside the existing loop
would not reduce request count versus the old REST flow, only swap the endpoint — CONTEXT.md is
explicit that this defeats the whole point of the phase. This plan is the first of the two callers
(batch-reload; Plan 3 covers bulk-import) that actually restructures its control flow to exploit
the batching.
Output: batchReload() resolves Wikidata for its entire eligible set in one prefetch step, then
threads the resulting map through the unchanged per-movie loop and pacing.
</objective>
