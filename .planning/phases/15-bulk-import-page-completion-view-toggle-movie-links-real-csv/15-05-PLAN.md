<objective>
Close UAT gap G-15-4: after 15-04's full-width fix made the resolve widget's candidate posters appropriately
sized, the user reported that each candidate still shows ONLY its poster image — no title or year text — which
makes picking the correct film hard or sometimes impossible when a poster is reused across regional releases,
remakes, or visually similar sequels (verbatim: "Ja, soweit funktioniert das eigentlich, allerdings werden halt
auch nur Poster angezeigt, was nicht ausreicht. Wir brauchen darunter auch den Titel und das Jahr.").

Root cause is already confirmed (no debugging needed): `candidate` is typed as `TmdbSearchResult`
(`frontend/composables/useMovies.ts`), which already carries `title: string` and `year: number | null` on every
search result. The data is available; it is simply never rendered as visible text today — `candidate.title` is
only ever used as the poster `<img alt="...">` attribute, and `candidate.year` is not referenced in the template
at all.

Purpose: make each resolve candidate identifiable enough to pick correctly, using data that already exists —
purely a template addition, no backend/composable/type changes.

Output: `[batchId].vue`'s grid-view and list-view resolve-candidate blocks both render a visible "Title (Year)"
(or "Title" alone when year is null) text label under each poster; `imports-batchId.spec.ts` extended with tests
proving the label renders in both views and degrades gracefully when year is null.
</objective>
